# Pack & Go 海報生成 Skill

把一團行程變成可以直接發出去的品牌海報。輸入是行程資訊,輸出是各平台尺寸的
PNG(必要時 PDF),全部走同一份 HTML 模板 + Chrome 渲染,所以五種尺寸長得一致。

## 這個 skill 存在的理由

以前發廣告是直接轉供應商的宣傳海報。那有三個問題:上面是供應商的品牌不是
Pack & Go 的、有時印著供應商的成本或同業價、而且圖片版權不在我們手上。
鐵閘寫得很清楚:供應商成本與供應商圖片不上客面。這個 skill 就是用來取代
「轉發供應商海報」這個動作的。

## 硬規則(違反就是事故,不是風格問題)

1. 供應商 invoice 金額是成本,絕不出現在海報上。海報只放最終售價。
   出圖前逐項比對報價來源,flyer 文字不可信(CLAUDE.md 紅線 2)。
2. 供應商的宣傳圖、截圖、行程圖一律不得當素材。只能用 Pack & Go 自有照片
   或已取得授權的圖庫圖。沒有合法圖就用模板內建的深藍漸層,不要將就。
3. 所有看得見的元素都要圓角。唯一例外是全寬 hero 背景圖(紅線 6)。
   模板已經處理好,不要為了「好看」把圓角拿掉。
4. 不可製造假急迫。「僅剩 6 位」只有在真的剩 6 位時才能寫;寫不出真數字就
   整塊拿掉,不要寫「錯過就沒了」。
5. 出發日、價格、含與不含,任何一項沒跟 Jeff 或報價單核對過就不出圖。
   模板裡的佔位資料原樣出街 = 事故。

## 公司資訊(海報頁尾固定)

```
公司名稱: Pack & Go, LLC
CST: #2166984-40
網站: packgoplay.com
電話: +1 (510) 634-2307
微信 / LINE: packgo
```

CST 字號一定要留著,那是合法旅行社的信任訊號,也是加州法規要求。

## 尺寸

| `--size` | CSS 尺寸 | 輸出 PNG | 用途 |
|----------|----------|----------|------|
| `wechat` | 1080×1350 | 1080×1350 | 微信朋友圈(預設,主戰場) |
| `line` | 1080×1350 | 1080×1350 | LINE 群發 |
| `square` | 1080×1080 | 1080×1080 | IG / FB 方形貼文 |
| `story` | 1080×1920 | 1080×1920 | IG / FB 限時動態、Reels 封面 |
| `print-a4` | 1240×1754 | 2480×3508 | 門市張貼、客人列印(300dpi) |

`print-a4` 出 `.pdf` 時會自動改用實體 A4(8.27×11.69 吋),長寬比一樣,版面不變。

## 生成流程

### 1. 收資料

沒有下面這些就先問,不要自己編:

- 目的地 / 系列名(眉標)
- 天數、團型(15 人小團 / 包車 / 郵輪)
- 3-4 個賣點
- 每人售價 + 價格附註(雙人房價?含什麼?)
- 出發日
- 名額(可省略)
- hero 照片路徑(可省略,省略就用漸層)

### 2. 核價(不能跳過)

售價要跟報價單或 Jeff 確認過的數字對得起來。供應商 invoice 只是成本輸入,
不是海報上的數字。對不上就停手問 Jeff。

### 3. 複製並改模板

```bash
cp references/template.html /tmp/poster-台灣八天.html
```

模板裡的內容全部是佔位,逐項換掉。**沒有的欄位整塊刪掉**,不要留「待確認」。
要換照片就改 `.hero` 的 `background-image`,並把照片放到跟 HTML 同一層。

### 4. 出圖

```bash
# 單一尺寸
node scripts/render.mjs /tmp/poster-台灣八天.html ~/Desktop/poster-wechat.png --size wechat

# 五種尺寸一次出
for s in wechat square story print-a4; do
  node scripts/render.mjs /tmp/poster-台灣八天.html ~/Desktop/poster-$s.png --size $s
done

# A4 PDF(給客人列印)
node scripts/render.mjs /tmp/poster-台灣八天.html ~/Desktop/poster-a4.pdf --size print-a4
```

渲染器會自己找 Chrome。找不到就設 `CHROME_PATH=<binary 路徑>`。

### 5. 讀回自檢(必做)

出完圖要真的把 PNG 讀出來看過再交。至少確認:

- 佔位假資料全部換掉了(尤其價格、日期、名額)
- 價格數字跟報價來源一致
- 頁尾電話、微信、CST 都在,沒被切掉
- 沒有供應商 logo / 供應商圖 / 成本數字
- 中文字沒有變成方塊(缺字型)

渲染器印出 `note: 已自動縮排至 0.9x 倍` 代表文案偏長被縮過,可以接受但建議刪一條
賣點換回標準字級。印出 `HALT: 版面溢出` 就是真的塞不下,圖上會有紅色警示條,
必須改文案重出,不能發。

## 文案規範

沿用行銷引擎那套標準,海報字少所以更嚴:

**主標(最大的字)**
- 14 字以內,最多兩行
- 講情緒收穫,不講規格
- 要有具體的東西,不要形容詞堆疊

好: 「不趕路的台灣八天七夜」「帶爸媽看極光,全程有人照顧」
壞: 「豪華台灣之旅」(空)、「超值優惠不容錯過!!!」(假急迫)

**眉標**:目的地 + 系列,例「台灣 · 環島深度」「阿拉斯加 · 郵輪」

**賣點(3-4 條)**
- 每條一行講完,18 字內,不要換行
- 針對長輩:舒適、尊嚴、被照顧
- 針對出錢的子女:放心
- 具體優先:「行李進房不用自己提」勝過「服務貼心」

**價格附註**:把「這個價含什麼」講清楚,避免客人事後有落差。

## 版面尺寸邏輯(要改模板時看這段)

模板所有長度都用 `--u` 換算,`--u = 畫布寬 / 1080`。所以照著 1080 寬的設計稿寫
數字就好,換到 A4 或限時動態會自動等比放大,不必重排。

垂直方向的分工:

- `.hero` — `flex: 1 0 auto`。內容短時吸收剩餘空間(照片變大),但絕不壓縮,
  所以主標永遠不會被切掉。
- `.body`、`.footer` — `flex: 0 0 auto`,照自己需要的高度長。
- 塞不下時由模板底部的 `autoFit` 腳本整體縮 `--u`(最多縮到 0.82),
  再塞不下就插紅色警示條。寧可醜到不可能誤發,也不要靜靜切掉價格或電話。

判定溢出的方法很直接:頁尾底邊掉出畫布就是溢出。

## 疑難排解

**中文變方塊**
系統缺繁體字型。Mac 有 PingFang TC 不會有問題;Linux 要裝 `fonts-noto-cjk`。

**出圖底部有一條空白**
不要改用 `chrome --screenshot`。headless Chrome 的 `--window-size` 給的是外框
尺寸,實際 viewport 會少 87px,截圖卻照外框輸出。`render.mjs` 走 CDP
(`Emulation.setDeviceMetricsOverride` + `Page.captureScreenshot` 帶 clip)就是為了
避開這個坑,而且會逐像素驗尺寸,不對就 HALT。

**照片沒出現**
照片要跟工作 HTML 放同一層,用相對路徑引用。`render.mjs` 會把相對資源一起
搬進暫存目錄;絕對路徑和 `../` 不會搬。

**Chrome 找不到**
`CHROME_PATH=/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome node scripts/render.mjs ...`

## 與其他 skill 的關係

- `packgo-marketing-engine` 產文案(標題、朋友圈、LINE、EDM)。海報主標可以直接
  從它產的標題挑一個。兩個一起用:先跑行銷引擎出文案,再用這個 skill 出圖。
- `packgo-quote` 產報價單 PDF。海報上的售價必須跟報價單對得起來。
- 海報是招攬用的宣傳品,不是報價文件。詳細行程、含與不含、取消政策放報價單,
  海報只放勾人的那幾句。
